## When this runs

Whenever a treatment page's copy, imagery or branding changes and the client
needs to see it on the web. Also re-run in full if the PureMed logo, the Nafisa
photo, or the brand palette changes, since all three are baked into every page.

## Prerequisites

- `python3` with Pillow available (`python3 -c "import PIL"`).
- Network access on first run only, to fetch the webfonts.
- Source prototypes present in `web/` (`puremed-<treatment>.html`). Six are hand-built;
  `puremed-sculptra.html` is generated by `tools/build-sculptra-source.py`.
- Image assets present in `assets/web/`.
- Claude Code session able to publish Artifacts.

## Routine operation

Run everything from the project root:
`~/workspace/main-stage-studio/02_clients/puremed/`

1. **Regenerate the Sculptra source.** It is derived from the shared template
   rather than hand-written, so it must be rebuilt before the pages are:
   ```
   python3 tools/build-sculptra-source.py
   ```
   Never hand-edit `web/puremed-sculptra.html`: that script overwrites it. Its copy
   lives in the constants at the top of the script.

2. **Refresh the font bundle** (first run, or if the type stack changes). This
   downloads the latin subsets of Cormorant Garamond and Inter and writes
   `tools/fonts-inline.css` (~720KB). Skip if that file already exists.

3. **Trim the logo** (only if the logo asset is replaced). The supplied logo has
   large transparent padding that renders the mark illegible at nav size:
   ```
   python3 -c "from PIL import Image; im=Image.open('assets/web/puremed_logo_transparent.webp').convert('RGBA'); im.crop(im.getchannel('A').getbbox()).save('assets/web/puremed-logo-trimmed.webp','WEBP',quality=92,method=6)"
   ```

4. **Build the self-contained pages:**
   ```
   python3 tools/build-microsites.py
   ```
   Expect seven `[ok]` lines in `web/publish/`, each 1.5–5.1 MB. Any line showing
   `!!` or `MISSING:` means an asset failed to resolve: stop and fix before
   publishing.

5. **Prepare Artifact fragments:**
   ```
   python3 tools/prep-artifacts.py tools/microsite-urls.json
   ```
   Expect `unresolved-links=0` on all seven. A non-zero count means a cross-page
   link has no entry in the URL map.

6. **Publish the seven pages** from `web/publish/_artifact/` as Artifacts. On a
   first-ever publish the URLs do not exist yet, so run step 5 without the JSON
   argument, publish to mint the URLs, record them in `tools/microsite-urls.json`,
   then re-run steps 5 and 6 so the cross-links resolve.

7. **Build and publish the hub:**
   ```
   python3 tools/build-hub.py
   ```
   Publish `web/publish/_artifact/index.html`. Add its URL to
   `tools/microsite-urls.json` under the key `index`.

8. **Share** the hub URL with the client from the Artifact page's share menu.
   Artifacts are private until explicitly shared.

## Checks

- Open the hub: seven cards, each with a face or treatment image, no blank tiles.
- Open one microsite: gold PUREMED wordmark legible in the navy nav bar, and the
  practitioner section near the foot showing the real clinic photo of Nafisa.
- In the nav, "About Nafisa", "Results" and "FAQ" scroll within the page; the
  "Treatments" dropdown jumps to the other live microsites.
- Grep for dead links before publishing:
  ```
  grep -o 'href="[^"]*\.html"' web/publish/_artifact/*.html
  ```
  Output should be empty.

## When it breaks

| Symptom | Likely cause | Fix |
|---|---|---|
| Published page renders blank | Document wrapper left in the file | Artifacts supply their own `<html>/<head>/<body>`; publish from `_artifact/`, never from `web/publish/` directly |
| Fonts fall back to Georgia/system | `tools/fonts-inline.css` missing or empty | Re-run step 2; the Artifact CSP blocks external font CDNs, so the faces must be inlined |
| Screenshot of a page comes out blank | Scroll-triggered `fade-up` never fired | Screenshot artefact only, not a page bug; neutralise animations before capturing |
| A card thumbnail shows a wall or empty room | That page's hero is a scene shot, not a portrait | Add an entry to `THUMB_OVERRIDE` in `tools/build-hub.py` |
| Artifact publish rejected for size | Page over 16 MB | Downsize the offending source image in `assets/web/` and rebuild |
| `no published Artifact URL for <slug>` | A new page has no entry in `tools/microsite-urls.json` | Publish that page first, record its URL, then rebuild the hub |

Escalation: source prototypes in `web/` are never modified by these scripts, so
any bad build can be fixed by deleting `web/publish/` and re-running from step 4.

## Boundaries

- **Never publish before/after client photography publicly without Nafisa's
  sign-off.** These pages carry real patient results.
- Do not use the AI-generated `nafisa-*` image library for anything client-facing:
  per the decisions log (6 Aug 2026) those likenesses do not resemble Nafisa and
  were rejected. Only `nafisa-hero-v2.webp` is approved.
- Do not reintroduce `#0B1F3A` as the brand navy; `#23476A` is the locked value.
- These scripts write only to `web/publish/`, `tools/`, and the trimmed logo.
  They do not touch `site/`, which is the version that actually ships.
